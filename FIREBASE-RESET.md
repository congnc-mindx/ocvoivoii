# Ocvoivoii — Firebase mới

Gói dành cho source hiện tại với CommunityPortal ở /register và hồ sơ Google player_profiles. Gói không tạo tài nguyên thật, không mang dữ liệu test và không chứa khóa đã điền.

1. Giải nén vào thư mục repo. Chỉ thay src/firebase.js, thêm firestore.rules, .env.example và hướng dẫn này. Không ghi đè .env.local.
2. Trong Firebase Console với nick mới, tạo project và app Web. Tạo Firestore Standard (default) ở Production mode. Bật Authentication → Sign-in method → Google. Thêm hostname GitHub Pages (không có /ocvoivoii/), domain riêng nếu có và localhost để thử vào Authentication → Settings → Authorized domains.
3. Đến Firestore Database → Rules trong project mới, thay toàn bộ bằng firestore.rules rồi Publish. Đây là file hoàn chỉnh; không dán thêm player-profiles.rules.part từ ZIP cũ. Có thể dùng lệnh macOS pbcopy < firestore.rules rồi dán vào Console.
4. Mở .env.local ở gốc repo. Giữ các biến khác, thay YOUTUBE_API_KEY bằng key mới. Thêm sáu dòng VITE_FIREBASE_* theo .env.example và điền đúng SDK Web config của project mới, tương ứng apiKey, authDomain, projectId, storageBucket, messagingSenderId và appId. Không dùng key YouTube cho Firebase. Nếu thiếu storageBucket và Messaging Sender ID thì để trống vì source này không dùng Storage hoặc Messaging. Không commit .env.local.
5. Chạy npm run dev và thử đăng nhập bằng nick mới. Trong Authentication → Users, lấy UID tại project mới. Tạo admin_users/{UID} trong Firestore Console: role (string) = admin, active (boolean) = true. Quyền Owner của project và admin trong ứng dụng là hai việc riêng. Route admin chưa có ở web công khai; quản trị dữ liệu qua Console.
6. Kết thúc cấu hình hồ sơ và đảm bảo player_profiles/{UID} được ghi vào project mới. Các trang giải/hệ sinh thái có thể trống vì chưa tạo event_sessions / ecosystem_brands. Giữ hộp đăng ký đóng đến khi sẵn sàng. Hồ sơ tuyển thủ chỉ cho chính chủ đọc qua web; admin có quyền xem hồ sơ giải và feedback qua rule. Khách có thể gửi form giải/góp ý đang mở theo thiết kế hiện tại nhưng không thể đọc lại.
7. GitHub → Settings → Secrets and variables → Actions → Secrets: cập nhật sáu VITE_FIREBASE_* và YOUTUBE_API_KEY. VITE_DISCORD_INVITE_URL là Repository Variable nếu dùng. Key YouTube mới cần YouTube Data API v3 trên project Google Cloud cấp key và nên bị giới hạn chỉ API đó. Nếu dùng runner GitHub-hosted và chạy script local, không đặt giới hạn kiểu Websites/HTTP referrers cho key chạy server. Chạy thử đồng bộ bằng npm run sync:youtube. Chỉ vô hiệu hóa key cũ sau khi đã thay ở cả local và GitHub.
8. Kiểm tra git status, npm run build rồi push như bình thường. Workflow đồng bộ YouTube trước bước build, nên lỗi YouTube có thể dừng deploy dù Firebase đã cấu hình đúng. Kiểm tra Actions trước khi thử login trên URL công khai.

Tên biến Discord có trong workflow của bản cập nhật hồ sơ. Nếu repo chưa ghép gói hồ sơ thì hãy ghép trước khi thử tính năng Google và link Discord. Rules này không bao gồm phiên bản đăng ký phân tự động 10+4 trong ZIP thử nghiệm trước đó.
